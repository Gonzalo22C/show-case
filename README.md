# Portafolio personal

Repositorio para desarrollar un portafolio que presente mi perfil, proyectos y servicios de forma clara, accesible y profesional.

## Público y objetivo

- **Empleadores:** Conocer mis habilidades, experiencia y contribuciones para evaluar oportunidades de contratación.
- **Clientes:** Entender los servicios que puedo ofrecer, revisar trabajos relevantes y encontrar un medio de contacto.

## Estado actual

**Implementado:** documentación inicial del proyecto, convenciones de trabajo, roadmap y exclusiones de Git.

**Propuesto:** la aplicación, las tecnologías, el diseño, los contenidos definitivos, la API REST y los diagramas. Todavía no existen pantallas, dependencias instaladas, scripts de ejecución ni pruebas automatizadas.

## Alcance inicial propuesto

- Presentación personal, perfil y habilidades.
- Selección de proyectos con contexto, mi contribución, resultados y enlaces disponibles.
- Servicios y contacto mediante enlaces; un formulario queda pendiente de definir junto con su backend.
- Navegación accesible, diseño responsive y temas claro/oscuro.
- Animaciones discretas que respeten la preferencia de movimiento reducido.

El roadmap contempla una API REST cuyo alcance se decidirá según necesidades reales. Autenticación, CMS, blog y panel administrativo quedan fuera del alcance inicial.

## Tecnologías propuestas

| Tecnología | Uso previsto | Estado |
| --- | --- | --- |
| Next.js | Estructura, rutas y renderizado del sitio | Propuesto |
| TypeScript | Tipado de componentes, datos y contratos | Propuesto |
| CSS Modules | Estilos locales y organización visual | Propuesto |
| Motion | Animaciones e interacciones con movimiento reducido | Propuesto |

Las versiones y dependencias se elegirán al iniciar la implementación; esta documentación no implica que estén configuradas.

## Trabajo en el repositorio

Consulta [AGENTS.md](AGENTS.md) para las convenciones y [docs/roadmap.md](docs/roadmap.md) para las fases y sus criterios de aceptación. No hay comandos de instalación, desarrollo o verificación definidos todavía. Se documentarán cuando existan y hayan sido ejecutados.

No se deben subir credenciales ni variables privadas. Si se necesita configuración, se podrá añadir `.env.example` con nombres y valores ficticios, nunca secretos.
